<p><strong>Microsoft's Desired State Configuration (DSC)</strong> is the new frontier in declarative configuration. It's a cross-platform CLI utility designed for infrastructure management. Whether you're working on a desktop, macOS, or Linux-based system, it can manage your system. </p><p>Unlike imperative tools, DSC cleanly separates the <em>what</em> from the <em>how</em>. You describe <em>what</em> the environment should be (for example," <em>this package must be installed")</em>. DSC then figures out <em>how</em> to bring the system into that particular state.</p><p><strong>What you'll learn:</strong><br><br>In this <em>getting started</em> module, you'll learn the fundamentals of working with Microsoft DSC. By the end of this module, you'll be able to:</p><ul><li>Understand what Microsoft DSC is.</li><li>Install Microsoft DSC on your system.</li><li>Discover and explore available DSC Resources.</li><li>Read and understand resource schemas.</li><li>Invoke individual resources using the <code>dsc</code> command-line interface.</li><li>Use the core resource operations: <code>get</code>, <code>set</code>, and <code>test</code>.</li><li>Manage system configuration through a practical example.</li></ul><h2 id="the-dsc-command-line-utility">The DSC command-line utility</h2><p>Compared to its predecessor (often referred to as <strong>PowerShell DSC</strong>), DSC provides a command-line utility (CLI) tool to manage components declaratively and idempotently. It runs on <strong>Linux, macOS, </strong>and <strong>Windows,</strong> requiring no external dependencies.</p><p>With DSC, you can:</p><ul><li>Author DSC resources to manage your systems in any language.</li><li>Invoke individual resources directly.</li><li>Create configuration documents that define the desired state of a system.</li></ul><h2 id="configuration-documents">Configuration documents</h2><p><strong>Configuration documents </strong>are the foundation of DSC. They're <strong>declarative data files </strong>that describe the desired state of a system by defining one or more resource instances.</p><p>In other words, a configuration document tells DSC <em>what</em> the system should look like once it’s properly configured.</p><p>You can write configuration documents in <strong>JSON</strong>, <strong>YAML, </strong>or <strong>Azure Bicep</strong>. Both formats are supported equally, allowing you to choose the one that best suits your workflow or tooling preferences.</p><h3 id="example-scenarios">Example scenarios</h3><p>You might use configuration documents to:</p><ul><li>Define the requirements for an application environment.</li><li>Enforce organizational or security configuration standards across systems.</li><li>Maintain consistency between development, test, and production environments.</li></ul><p>Imagine you want to set the system locale to a different language. The following <strong>configuration document </strong>illustrates this:</p><pre><code class="language-yaml">$schema: https://aka.ms/dsc/schemas/v3/bundled/config/document.json
resources:
  - name: Set system locale to en-US
    type: ComputerManagementDsc/SystemLocale
    properties:
      IsSingleInstance: 'Yes'
      SystemLocale: en-US</code></pre><p></p><h2 id="dsc-resources">DSC Resources</h2><p><strong>DSC Resources </strong>define how to manage the state of a specific system or application component.<br>Each resource provides a <strong>schema</strong> that describes the settings it can manage and the operations it supports.</p><p>In simple terms, a DSC Resource knows <strong>what it can control</strong> and <strong>how to ensure it remains in the desired state.</strong></p><h3 id="resource-operations">Resource operations</h3><p>Each resource can support one or more of the following operations:</p><ul><li><strong>Get</strong> – Retrieves the current state of a resource instance.</li><li><strong>Test</strong> – Checks whether the current state matches the desired state.</li><li><strong>Set</strong> – Enforces the desired state (supported by most resources).</li><li><strong>Delete</strong> – Removes or resets a resource instance if it’s no longer needed.</li><li><strong>Export</strong> – Captures the current configuration of a resource, allowing it to be reused or versioned elsewhere.</li></ul><p>These operations allow DSC to both <strong>validate</strong> and <strong>control</strong> the configuration of a system in an idempotent way — meaning that applying the same configuration repeatedly won’t cause unexpected changes.</p><h3 id="example-scenarios-1">Example scenarios</h3><p>You might use DSC Resources to:</p><ul><li>Update the contents of a configuration file.</li><li>Run a command-line utility to adjust system settings.</li><li>Configure application parameters or deployment values.</li><li>Remove obsolete configuration items or services.</li><li>Export current configuration data for auditing or backup purposes.</li></ul><p>Instead of defining a full configuration document, you can <strong>invoke a resource directly</strong> using the DSC CLI. The following command tests if the system locale is actually set to <code>en-US</code> using the <code>ComputerManagementDsc/SystemLocale</code> resource:</p><pre><code class="language-powershell"># Pipe the input to dsc resource set
'{"IsSingleInstance":"Yes","SystemLocale":"ja-JP"}' | dsc resource test -r ComputerManagementDsc/SystemLocale</code></pre><p></p><h2 id="differences-from-powershell-dsc">Differences from PowerShell DSC</h2><p>While DSC shares some concepts with <strong>PowerShell Desired State Configuration (PSDSC)</strong>, it differs in several important ways. Understanding these differences helps you leverage DSC more effectively, especially in cross-platform environments.</p><h3 id="no-powershell-dependency">No PowerShell dependency</h3><p>Instead, DSC provides full compatibility with PSDSC resources through <strong>adapter resources</strong>:</p><ul><li><strong><code>Microsoft.DSC/PowerShell</code> adapter</strong><ul><li>Supports PSDSC resources implemented as PowerShell classes.</li><li>Handles discovery, validation, and invocation of these resources.</li><li>Included in the DSC install package on all platforms.</li></ul></li><li><strong><code>Microsoft.Windows/WindowsPowerShell</code> adapter</strong><ul><li>Supports PSDSC resources compatible with Windows PowerShell.</li><li>Handles discovery, validation, and invocation in Windows PowerShell.</li><li>Included in DSC install packages for Windows only.</li></ul></li></ul><div class="kg-card kg-callout-card kg-callout-card-blue"><div class="kg-callout-emoji">ℹ️</div><div class="kg-callout-text">Because DSC does not require PowerShell, you can manage resources implemented in <b><strong style="white-space: pre-wrap;">Bash, Python, C#, Rust, or any other language</strong></b>, even on systems without PowerShell installed.</div></div><p></p><h3 id="no-local-configuration-manager">No Local Configuration Manager</h3><p>DSC does <strong>not</strong> include a local configuration manager. It runs as a <strong>command-line tool</strong>, not as a background service.</p><p>This means DSC configurations are applied <strong>on demand</strong> when invoked, rather than continuously monitored by a service.</p><h3 id="schema-definition-format">Schema definition format</h3><p>New DSC resources define their schemas using <strong>JSON</strong> or <strong>YAML</strong>, instead of <strong>MOF</strong> files.</p><ul><li><strong>Self-contained resources</strong> include a <strong>resource manifest</strong> specifying:<ul><li>How DSC should invoke the resource.</li><li>What properties the resource can manage.</li></ul></li><li><strong>Adapted resources</strong> (e.g., PowerShell-based) rely on their adapter resource to:<ul><li>Discover available properties.</li><li>Invoke the resource correctly.</li></ul></li></ul><h3 id="configuration-documents-format">Configuration documents format</h3><p>DSC configuration documents are authored in <strong>JSON</strong> or <strong>YAML</strong>, not PowerShell scripts.</p><p>These documents support a subset of <strong>Azure Resource Manager (ARM) template</strong> features, including:</p><ul><li>Parameters</li><li>Variables</li><li>Metadata</li><li>Expression functions</li></ul><div class="kg-card kg-callout-card kg-callout-card-blue"><div class="kg-callout-emoji">ℹ️</div><div class="kg-callout-text">These capabilities allow you to dynamically resolve values and customize configurations at runtime.</div></div><p></p><h2 id="next-up">Next up</h2><p>You have now learned about Microsoft Desired State Configuration (DSC). It's time to install <code>dsc</code> on your machine in the next lesson.</p>
